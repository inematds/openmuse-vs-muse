Your AI agent: in Meta's cloud or on your own server?

Meta Muse and OpenMuse (CopilotKit, MIT license) promise the same idea: an agent with its own computer and browser, which you watch work. We compared them point by point and checked every claim against a primary source.

See the comparison What was verified
What it is

Two agents, the same core idea

This page starts from a comparison video published on YouTube (in German) and checks its claims against Meta's official announcement, press coverage, and OpenMuse's own code on GitHub.

☁️ Meta Muse

Personal agent launched by Meta on Sep 8, 2026. Every user gets a dedicated secure VM in Meta's cloud, with a Chromium browser they can watch and take over. Free, $20 and $100/month plans.

🖥️ OpenMuse

CopilotKit's open source answer, created Sep 15, 2026, MIT license. Runs on your own server: Expo app (iOS/Android/web), Hono API, a Playwright-driven browser and a Linux computer in Docker, both optional. It's in alpha.

🔎 This analysis

Most of the video's claims hold up. There are notable errors: the $18 billion settlement is stated once as "million," the "Pika Light" database is actually PGlite, and OpenMuse does depend on an external service.

Usage guide · step by step

Run OpenMuse on your own machine

Commands taken from the official README (Sep 28, 2026). Since the project is in alpha, check the repository first, as steps may change.

1

Prerequisites

Node 24 LTS, pnpm 11.19.0, and a CopilotKit account, required for the Intelligence key.

node -v              # v24.x
corepack enable && corepack prepare pnpm@11.19.0 --activate
2

Clone and install

Install with the lockfile pinned to reproduce the project's exact versions.

git clone https://github.com/CopilotKit/OpenMuse.git openmuse
cd openmuse
pnpm install --frozen-lockfile
cp .env.example .env
3

Generate the CopilotKit Intelligence key

This is the step the video skips. The key stays only on the server, in .env.

npx copilotkit@latest login
npx copilotkit@latest project select
# paste the generated key into .env:  CPK_INTELLIGENCE_API_KEY=...
4

Start the API and the web app

Two terminals. The sample app runs without a model, a Google account, or Docker.

pnpm dev        # terminal 1: API + task worker
pnpm dev:web    # terminal 2: web interface
5

Try the local demos

Three demos use a test inbox, without touching anything real: fill out an outing permission slip (generates the PDF and drafts the reply), create a goal that monitors a page, and import sample transactions to see the spending summary.

6

Optional: your own browser and computer

The real browser requires Chromium and a token that protects the connection. The Linux computer runs in Docker.

pnpm dev:browser                 # Playwright/Chromium worker
COMPUTER_ENABLED=true pnpm dev   # turns on the Linux computer in Docker
7

Optional: real Gmail and Calendar

In .env: WORKSPACE_MODE=live, OPENMUSE_ACCESS_KEY (24+ random characters) and TOKEN_ENCRYPTION_KEY (32 bytes in base64), plus Google's OAuth credentials. Then restart the API.

openssl rand -base64 32   # value for TOKEN_ENCRYPTION_KEY
Verdict

Which one makes sense for you

The video's conclusion holds up: OpenMuse matches Muse's core idea, but not yet its polish or its reach.

☁️ Choose Muse if…

  • you want to open the app and use it, with no setup;
  • you need voice, Meta glasses, or real purchases;
  • you're fine giving Meta access to email and calendar in exchange for convenience.

🖥️ Choose OpenMuse if…

  • you want your data on your own server;
  • you want to read, change and extend the code (MIT);
  • you're up for dealing with alpha software, .env, Docker, and the CopilotKit key.
"Free" doesn't mean "no effort." The cost moves from your card to your terminal: hosting, the key for whatever model you connect, and maintaining a project that still changes every week.
